# UI/UX Fixes Summary

## 1. Prevent Entrance Animations Re-playing
**Findings:** 
The `react-native-reanimated` entrance animations (like `FadeInUp` and `FadeInDown`) were executing on every mount or re-render of the screen, which is undesirable when navigating back from child screens (like the calendar view) where the stack causes a re-focus or re-render.

**Changes Applied:**
- Implemented a local `useIsFirstRender` hook in `app/room/[id].tsx` which uses a `useRef` and `useEffect` to reliably track if it is the first time the component renders.
- Conditionally applied the `entering` prop to all `Animated.View` components (e.g., `entering={isFirstRender ? FadeInUp.duration(600) : undefined}`).
- Passed the `isFirstRender` boolean to the decoupled `NudgeAllBanner` and `MemberRow` components so they could apply the same conditionally-rendered behavior.

## 2. Fix Unwanted Scrollable Space at Bottom
**Findings:**
The extra bottom padding was being generated by a common React Native layout engine anomaly: `marginTop: "auto"` applied to the `footer` nested within a `ScrollView` with `contentContainerStyle={{ flexGrow: 1 }}`. When `marginTop: "auto"` is combined with `flexGrow: 1`, the flex container calculations can inflate the scrollable area beyond the actual content boundaries. 

**Changes Applied:**
- Removed `marginTop: "auto"` from the `footer` style definition in `app/room/_[id].styles.ts`.
- Introduced a transparent `flex: 1` spacer `<View style={{ flex: 1 }} />` immediately preceding the `footer` in `app/room/[id].tsx`. This method acts structurally identical to margin-auto—pinning the footer to the bottom on shorter screens while gracefully collapsing on overflowing content—without triggering the intrinsic height calculation bugs in `ScrollView`.
